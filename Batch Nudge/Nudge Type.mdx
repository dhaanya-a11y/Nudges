**Nudge Type** defines how a Nudge is triggered and the source of information used to initiate it.

During Nudge creation, select the Nudge Type that matches the required trigger mechanism and customer information source.

<Info>
The selected **Nudge Type** determines the configuration flow available in the subsequent stages of Nudge creation.
</Info>

## Available Nudge Types

Hyperface supports the following Nudge Types:

<CardGroup cols={3}>
  <Card title="System Nudge">
    Triggered using customer parameters available in the system.
  </Card>
  <Card title="File Upload">
    Triggered using a `.csv` file containing customer information.
  </Card>
  <Card title="Journey Nudge">
    Triggered by touchpoints within a customer journey.
  </Card>
</CardGroup>

## Comparison

| Consideration | System Nudge | File Upload | Journey Nudge |
| --- | --- | --- | --- |
| **Trigger Mechanism** | System-based triggers | `.csv` file | Journey touchpoints |
| **Information Used** | Customer parameters available in the system | Customer information provided in the file | Information from the customer journey |
| **Communication Context** | System-driven | File-based | Journey-based |

## System Nudge

A **System Nudge** uses **system-based triggers** to initiate a Nudge.

The trigger can use customer parameters available in the system. These parameters can be included in the configured criteria used to determine when the communication should be triggered.

Examples of customer parameters include:

- **Card details**
- **Card status**
- **Date of birth**

<Steps>
  <Step title="Configure customer parameters">
    Required customer parameters are configured as part of the Nudge criteria.
  </Step>
  <Step title="System triggers communication">
    The system uses the configured information to trigger the communication when the criteria are met.
  </Step>
</Steps>

<Accordion title="Example">
A Nudge needs to be triggered based on a customer's **card status**. The configured card-status information forms part of the criteria used to trigger the communication.
</Accordion>

## File Upload

A **File Upload** Nudge uses a **`.csv` file** to provide the customer information required for the Nudge.

The file can contain a defined set of customers for whom the Nudge needs to be triggered. This provides the customer set through a file rather than using customer parameters available in the system.

<Steps>
  <Step title="Prepare the customer set">
    A customer set is prepared in a **`.csv` file**.
  </Step>
  <Step title="Upload as part of configuration">
    The file is provided as part of the Nudge configuration and used to trigger the Nudge for the specified customer set.
  </Step>
</Steps>

<Accordion title="Example">
A bank has a predefined set of customers who need to receive a particular communication. The customer information is provided in a **`.csv` file**, which is then used to trigger the Nudge for that customer set.
</Accordion>

## Journey Nudge

A **Journey Nudge** uses **touchpoints within a customer journey** to trigger a Nudge.

The communication can be delivered through the following channels:

- **SMS**
- **WhatsApp**
- **Email**

The communication includes a link that directs the customer to a **landing page**. Information from the previous journey step is retained on the landing page, allowing the customer to continue from the previous step and proceed to the **next step** of the journey.

<Steps>
  <Step title="Customer reaches a touchpoint">
    The customer reaches a configured touchpoint within a journey.
  </Step>
  <Step title="Communication is sent">
    The Journey Nudge provides a communication through **SMS, WhatsApp, or Email** containing a link to the landing page.
  </Step>
  <Step title="Customer continues the journey">
    Information from the previous journey step is retained on the landing page, allowing the customer to proceed to the next step.
  </Step>
</Steps>

<Accordion title="Example">
A customer reaches a configured touchpoint within a journey. A **Journey Nudge** provides a communication through **SMS, WhatsApp, or Email** containing a link to the landing page. The information from the previous journey step is retained, allowing the customer to continue to the next step.
</Accordion>

## Choosing a Nudge Type

- **System Nudge** — Select when the trigger uses **customer parameters available in the system**.
- **File Upload** — Select when the customer information is provided through a **`.csv` file**.
- **Journey Nudge** — Select when the trigger is associated with a **touchpoint within a customer journey**.

<Note>
The available configuration options and subsequent steps depend on the selected **Nudge Type**.
</Note>
