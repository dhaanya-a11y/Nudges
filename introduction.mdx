## Overview

**Nudges** are customer communications designed to encourage customers to take the **next action toward a defined goal**.

A Nudge can communicate an **action, reminder, or benefit** based on configured criteria. It can be presented as an **in-app experience**, such as a PWA banner, or delivered through external communication channels such as **SMS, WhatsApp, RCS, and Email**.

<Info>
A Nudge combines four key elements — **Eligibility, What to Send, How to Send, and When to Send** — to define the customer communication.
</Info>

## How a Nudge Works

A Nudge is configured using four key components. Together, these components determine:

* **Who** should receive the communication
* **What** communication should be sent
* **How** the communication should be delivered
* **When** the communication should be triggered

### 1. Eligibility

**Eligibility** defines the customers to whom the Nudge applies.

Customer parameters and configured criteria determine which customers qualify for the Nudge.

For example, a **System Nudge** can use customer parameters such as:

* **Card details**
* **Card status**
* **Date of birth**

These parameters are evaluated against the configured criteria to determine which customers are eligible for the Nudge.

### 2. What to Send

**What to Send** defines the content that is presented or delivered to the customer.

The communication is created using a configured **template**, which contains the message to be communicated.

For example:

> **"Hi, complete the goal to unlock your reward."**

### 3. How to Send

**How to Send** defines the communication channel through which the Nudge reaches the customer.

The available channels are:

| Channel      | Description                                                   |
| ------------ | ------------------------------------------------------------- |
| **PWA**      | Presents the Nudge as an in-app experience, such as a banner. |
| **SMS**      | Communicates the configured message through a text message.   |
| **WhatsApp** | Shares the configured message through WhatsApp.               |
| **RCS**      | Provides the configured communication through RCS.            |
| **Email**    | Communicates the configured message through Email.            |


### 4. When to Send

**When to Send** defines when the Nudge is triggered.

The configured trigger determines the point at which the communication is sent to the customer.

<Tip>
For example, a Nudge can be configured to be sent at **5:00 PM on October 20, 2026**.
</Tip>

## Nudge Types

Nudges are available in different types based on how they are triggered or configured.

<CardGroup cols={2}>

<Card title="System Nudge" icon="gear">
Uses **system-based triggers** and customer parameters such as **card details, card status, and date of birth**.
</Card>

<Card title="File Upload" icon="file-arrow-up">
Uses a **`.csv` file upload** to trigger Nudges.
</Card>

<Card title="Journey Nudge" icon="route">
Sends a Nudge through **SMS, WhatsApp, or Email** with a link that directs the customer to a **landing page**. Information from the previous journey step is retained on the landing page, allowing the customer to proceed to the **next step**.
</Card>

<Card title="Promotional Nudge" icon="tag">
Uses **datapoints across offers** to trigger a Nudge.
</Card>

<Card title="Cross Sell / Up Sell" icon="arrow-up-right">
Uses **EMI-related attributes** to create a Nudge.
</Card>

<Card title="Other" icon="gift">
Delivers value through **gift vouchers**.
</Card>

</CardGroup>

<Note>
The configuration and options available for a Nudge depend on the selected **Nudge Type**.
</Note>

## Summary

A Nudge defines a customer communication by specifying **who is eligible, what is communicated, how it is delivered, and when it is triggered**. The available configuration options depend on the selected Nudge Type.
