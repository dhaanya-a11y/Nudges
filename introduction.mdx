## Overview

**Nudges** are customer communications designed to encourage customers to take the **next action toward a defined goal**.

A nudge can communicate an **action, reminder, or benefit** based on the configured criteria. It can be presented as an **in-app experience**, such as a PWA banner, or delivered through external communication channels including **SMS, WhatsApp, RCS, and Email**.

<Info>
A Nudge brings together **Eligibility, What to Send, How to Send, and When to Send** to define the customer communication.
</Info>

## How a Nudge Works

A nudge is configured around four key components. Together, these components define **who should receive the communication, what they should receive, how it should be delivered, and when it should be triggered**.

### 1. Eligibility

**Eligibility** defines the customers to whom the nudge applies.

The configured customer parameters and criteria determine which customers qualify for the nudge.

For example, a **System Nudge** can use customer parameters such as:

- **Card details**
- **Card status**
- **Date of birth**

These parameters are used to determine the customers who meet the configured criteria.

### 2. What to Send

**What to Send** defines the content that is presented or delivered to the customer.

The communication is created using a configured **template**, which contains the message to be communicated.

**Example:**

> **"Hi, complete the goal to unlock your reward."**

### 3. How to Send

**How to Send** specifies the communication channel through which the nudge reaches the customer.

The available channels are:

- **PWA** — Presents the nudge as an in-app experience, such as a banner.
- **SMS** — Delivers the configured communication through a text message.
- **WhatsApp** — Delivers the configured communication through WhatsApp.
- **RCS** — Delivers the configured communication through RCS.
- **Email** — Delivers the configured communication through Email.

### 4. When to Send

**When to Send** defines when the nudge is triggered.

The configured trigger determines the point at which the communication is sent to the customer.

<Tip>
For example, a nudge can be configured to be sent at **5:00 PM on October 20, 2026**.
</Tip>

## Nudge Types

Nudges are available in different types based on how they are triggered or configured.

| **Nudge Type** | **Description** |
|---|---|
| **System Nudge** | Uses system-based triggers and customer parameters such as **card details, card status, and date of birth**. |
| **File Upload** | Uses a **`.csv` file upload** to trigger nudges for the customer information provided through the file. |
| **Journey Nudge** | Sends a nudge through **SMS, WhatsApp, or Email** with a link to a **landing page**. Information from the previous journey step is retained on the landing page, allowing the customer to proceed to the **next step**. |
| **Promotional Nudge** | Uses **datapoints across offers** to trigger a nudge. |
| **Cross Sell / Up Sell** | Uses **EMI-related attributes** to create a nudge. |
| **Other** | Delivers value to customers through **gift vouchers**. |

<Note>
The configuration and options available during nudge creation depend on the selected **Nudge Type**.
</Note>
