## Overview

The **User Base** defines the group of customers who are eligible to receive the nudge.

In this step, configure the criteria used to identify the target users. The user base can be defined using attributes available under different entities such as **Customer**, **Account**, **Card**, and **Card Control**.

You can also estimate the number of users matching the configured criteria and configure additional controls for communication and duplicate accounts.

## Set Up Nudge User Base

### User Base

The **User Base** section allows you to define the conditions used to identify customers for the nudge.

Each criterion consists of:

- An **entity**, such as Customer, Account, Card, or Card Control.
- An **attribute** associated with the selected entity.
- The corresponding value or condition used to define the user base.

Select the required entity from the first dropdown and then select an attribute from **Select attribute**.

The attributes available in the second dropdown depend on the selected entity.

### Add Criteria

Select **Add Criteria** to add additional conditions to the user base.

Multiple criteria can be configured when the nudge needs to target users based on more than one condition.

The available customer attributes include:

| Attribute | Description |
|---|---|
| **Date of Birth** | The customer's date of birth. This attribute can be used to identify customers based on their date of birth or age. |
| **KYC Status** | **KYC (Know Your Customer)** is the process of verifying a customer's identity. This attribute indicates the customer's current KYC verification status. |
| **FKYC Method** | **FKYC (Full KYC)** refers to the customer's full KYC verification. This attribute indicates the method through which the customer's FKYC was completed. |
| **FKYC Status** | Indicates the current status of the customer's **Full KYC (FKYC)** verification. |
| **Created On** | The date on which the customer's record was created in the system. |
| **Last Updated On** | The date on which the customer's record was most recently updated in the system. |

### Account Attributes

The following attributes are available for selection under **Account**:

- **Status** — Used to define a criterion based on the account status.
- **Smart Tag** — Used to define a criterion based on the Smart Tag associated with the account.
- **Statement Due Date** — Used to define a criterion based on the account's statement due date.
- **Created On** — Used to define a criterion based on the account creation date.
- **Last Updated On** — Used to define a criterion based on the date the account was last updated.
- **Account Block Codes** — Used to define a criterion based on the block codes associated with the account.

### Add Account Criteria

Select the required attribute from the **Account** attribute dropdown and configure the corresponding condition.

Select **Add Criteria** to add additional conditions to the user base.

### Available Card Attributes

The following attributes can be selected when defining criteria for the card:

#### Card Status and Identification

- **Status** — The current status of the card.
- **Smart Tag** — The Smart Tag associated with the card.
- **Card Type** — The type of card.
- **Card Block Codes** — The block codes associated with the card.

#### Card Lifecycle

- **Card Expiry** — The expiry details of the card.
- **Physically Issued** — The physical card issuance status.
- **Virtually Issued** — The virtual card issuance status.
- **Physical Card Activated** — The activation status of the physical card.
- **Virtual Card Activated** — The activation status of the virtual card.
- **Is Ever Activated** — The card's activation history.

#### Card State

- **Locked** — The locked status of the card.
- **Blocked** — The blocked status of the card.

#### Record Information

- **Created On** — The date on which the card record was created.
- **Last Updated On** — The date on which the card record was last updated.
## Card Control

Select **Card Control** to define user-base criteria using card-control attributes.

The available attributes are grouped into **Domestic Controls** and **International Controls** based on the transaction context.

### Domestic Controls

Domestic Controls relate to transaction types performed within the domestic region.
- **Domestic Contact** — Transactions made using contact-based card payments within the domestic region.
- **Domestic Contactless** — Transactions made using contactless card payments within the domestic region.
- **Domestic Ecommerce** — Online purchases or payments made through ecommerce platforms within the domestic region.
- **Domestic Magnetic** — Transactions made using the card's magnetic stripe within the domestic region.
- **Domestic Moto** — Mail-order and telephone-order transactions where the card is not physically presented within the domestic region.
- **Domestic Cash** — Cash transactions, such as cash withdrawals, within the domestic region.

### International Controls

International Controls relate to transaction types performed outside the domestic region.
- **International Contact** — Transactions made using contact-based card payments outside the domestic region.
- **International Contactless** — Transactions made using contactless card payments outside the domestic region.
- **International Ecommerce** — Online purchases or payments made through ecommerce platforms outside the domestic region.
- **International Magnetic** — Transactions made using the card's magnetic stripe outside the domestic region.
- **International Moto** — Mail-order and telephone-order transactions where the card is not physically presented outside the domestic region.
- **International Cash** — Cash transactions, such as cash withdrawals, outside the domestic region.

## Additional User Base Controls

After defining the user-base criteria, the following options are available to control communication eligibility and duplicate accounts.

### Override Do Not Communicate (DNC)

Enable **Override Do Not Communicate (DNC)** to allow the nudge to be sent to eligible customers who are part of the **Do Not Communicate (DNC)** list.

### Allow Duplicate Accounts

Enable **Allow Duplicate Accounts** when duplicate accounts should be included in the nudge's user base.

By default, duplicate accounts are blocked to prevent customers from receiving multiple communications. This option should be enabled only for pre-approved campaigns where duplicate accounts are intentionally required.
