## Overview

**Nudge Type** determines how a Nudge is triggered and the source of information used to initiate it.

During Nudge creation, select the type that matches the required trigger mechanism and customer information source.

Hyperface supports the following Nudge Types:

- **System Nudge**
- **File Upload**
- **Journey Nudge**

## Nudge Type Comparison

The following table provides a quick comparison of the supported Nudge Types.

| Consideration | System Nudge | File Upload | Journey Nudge |
| --- | --- | --- | --- |
| **Trigger Mechanism** | System-based triggers | `.csv` file | Journey touchpoints |
| **Information Used** | Customer parameters available in the system | Customer information provided in the file | Information from the customer journey |
| **Communication Context** | System-driven | File-based | Journey-based |

## System Nudge

A **System Nudge** uses **system-based triggers** to initiate a Nudge.

The trigger can use customer parameters available in the system. These parameters can be included in the configured criteria used to determine when the communication should be triggered.

Examples of customer parameters include:

- **Card details**
- **Card status**
- **Date of birth**

### How It Works

The required customer parameters are configured as part of the criteria for the Nudge. The system uses the configured information to trigger the communication when the criteria are met.

### Example

A Nudge needs to be triggered based on a customer's **card status**.

The configured card-status information forms part of the criteria used to trigger the communication.

## File Upload

A **File Upload** Nudge uses a **`.csv` file** to provide the customer information required for the Nudge.

The file can contain a defined set of customers for whom the Nudge needs to be triggered. This provides the customer set through a file rather than using customer parameters available in the system.

### How It Works

A customer set is prepared in a **`.csv` file** and provided as part of the Nudge configuration. The information in the file is used to trigger the Nudge for the specified customer set.

### Example

A bank has a predefined set of customers who need to receive a particular communication.

The customer information is provided in a **`.csv` file**, which is then used to trigger the Nudge for that customer set.

## Journey Nudge

A **Journey Nudge** uses **touchpoints within a customer journey** to trigger a Nudge.

The communication can be presented through the following channels:

- **SMS**
- **WhatsApp**
- **Email**

The communication includes a link that directs the customer to a **landing page**.

Information from the previous journey step is retained on the landing page. This allows the customer to continue from the previous step and proceed to the **next step** of the journey.

### How It Works

The customer reaches a configured touchpoint within a journey. The Journey Nudge then provides a communication through **SMS, WhatsApp, or Email**.

The communication contains a link to the landing page. When the customer accesses the landing page, information from the previous journey step is retained, allowing the customer to proceed to the next step.

### Example

A customer reaches a configured touchpoint within a journey.

A **Journey Nudge** provides a communication through **SMS, WhatsApp, or Email** containing a link to the landing page. The information from the previous journey step is retained on the landing page, allowing the customer to continue to the next step.

## Choosing a Nudge Type

Select the Nudge Type based on the source used to initiate the Nudge:

- Select **System Nudge** when the trigger uses **customer parameters available in the system**.
- Select **File Upload** when the customer information is provided through a **`.csv` file**.
- Select **Journey Nudge** when the trigger is associated with a **touchpoint within a customer journey**.

<Note>
The available configuration options and subsequent steps depend on the selected **Nudge Type**.
</Note>
